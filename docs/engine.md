# Vault Rush — Deterministic Puzzle Engine

The same engine is implemented twice, byte-for-byte compatible:

- `backend/pkg/engine` (Go) — authoritative, used by the server to **replay** every finished run.
- `client/src/engine` (TypeScript) — used by the client to play.

A cross-language golden test (`backend/pkg/engine/testdata/fixtures.json`, generated by Go, asserted by Vitest) guarantees both produce identical boards, loot and scores for identical seeds and moves.

Because the engine is deterministic, the server never stores a board. A run is just
`{runId, playerId, seed, configVersion, boosters}`; everything else is reproducible.

---

## 1. Tiles

| id | name    | role       | base loot |
|----|---------|------------|-----------|
| 0  | KEY     | objective  | 40        |
| 1  | LASER   | objective  | 40        |
| 2  | CAMERA  | objective  | 40        |
| 3  | MONEY   | loot       | 100       |
| 4  | DIAMOND | loot       | 250       |
| 5  | GUARD   | bonus      | 30 (+1 move per chain) |
| 6  | LOCK    | obstacle   | — (cannot be chained) |

Grid is `w × h` (default 7×7). Cell index `i = row * w + col`, row 0 is the **top**.

## 2. RNG — mulberry32

State: one `uint32`, seeded with the run seed (`uint32(seed)`).

```
next():
  s = s + 0x6D2B79F5           (mod 2^32)
  t = (s ^ (s >> 15)) * (1 | s) (mod 2^32)
  t = (t + ((t ^ (t >> 7)) * (61 | t))) ^ t   (mod 2^32)
  return t ^ (t >> 14)          (uint32)

nextInt(n) = next() % n
```

All arithmetic is unsigned 32-bit. In JS use `Math.imul` and `>>> 0`. **Never** use floats from the RNG.

A run uses **one RNG stream** for its whole lifetime (all vaults, all refills). Any divergence in call order breaks determinism, so the order below is normative.

## 3. Weighted tile draw

`randomTile(weights)`: `total = key+laser+camera+money+diamond+guard`; `r = nextInt(total)`; walk types in order KEY, LASER, CAMERA, MONEY, DIAMOND, GUARD subtracting weights; the first type where `r < weight` is returned.

## 4. Vault setup

```
generateBoard(vault):
  for i in 0..w*h-1: grid[i] = randomTile(vault.weights)      // row-major
  placed = 0
  while placed < vault.locks:
    idx = nextInt(w*h)
    if grid[idx] != LOCK: grid[idx] = LOCK; placed++
  if !hasAnyMove(grid): reshuffle(grid)
```

`reshuffle`: for `i` in row-major order, every non-LOCK cell gets `randomTile(weights)`; repeat until `hasAnyMove` (bounded by 100 attempts, then accept).

`hasAnyMove`: true iff some non-LOCK cell has **≥ 2 same-type 8-neighbours** (that is exactly the condition for a 3-chain to exist).

Objectives are scaled by difficulty using integer math:

```
d   = round(difficulty * 100)            // 1.25 → 125
req = floor((base * d + 50) / 100)       // round-half-up
```

Moves for the vault: `vault.moves + (boosters includes "extra_moves" ? 3 : 0)`.

## 5. A move (chain)

A move is an ordered list of cell indices `path`:

- `len(path) ≥ 3`
- all indices in range, all distinct
- every cell has the same type `T`, and `T != LOCK`
- consecutive cells are 8-adjacent (`|dr| ≤ 1 && |dc| ≤ 1`)

Chain multiplier (percent): `len 3 → 100`, `4 → 150`, `5 → 200`, `≥6 → 300`.

```
applyMove(path):
  T   = type of path[0]
  pct = chainPct(len)
  loot += floor(len * baseLoot[T] * pct / 100)
  if T in {KEY, LASER, CAMERA}: objectives[T] = max(0, objectives[T] - len)
  movesLeft -= 1
  if T == GUARD: movesLeft += 1

  // unlock: LOCK cells orthogonally adjacent (4-neighbourhood) to any removed cell
  for idx in ascending index order over the whole grid:
    if grid[idx] == LOCK and has 4-neighbour in path: grid[idx] = randomTile(weights)

  for idx in path: grid[idx] = EMPTY
  collapseAndRefill()

  if all objectives == 0:  vault → CRACKED
  else if movesLeft == 0:  vault → BUSTED
  else if !hasAnyMove(): reshuffle()
```

`collapseAndRefill()`:
```
for col in 0..w-1:
  // gravity: non-empty cells keep relative order and settle to the bottom
  write = h-1
  for row from h-1 down to 0:
    if grid[row][col] != EMPTY: grid[write][col] = grid[row][col]; write--
  // refill from the top down
  for row from 0 to write: grid[row][col] = randomTile(weights)
```

## 6. Run flow and scoring

```
totalLoot = 0
for vaultIndex, vaultReplay in replay.vaults:
  setupVault(config.vaults[vaultIndex])
  for move in vaultReplay.moves:
    if vault state != PLAYING: INVALID (moves after crack/bust)
    applyMove(move)              // INVALID if illegal
  if state == PLAYING: INVALID   // vault left unfinished
  if state == BUSTED and vaultIndex != last replay vault: INVALID
  totalLoot = engine loot so far

vaultReached = number of replay vaults
if last vault CRACKED:
  if replay.escaped == false and vaultReached < len(config.vaults): INVALID (must go deeper or escape)
  outcome = ESCAPED, mult = vaultMultipliers[vaultReached-1]
  score = roundHalfUp(totalLoot * mult * lootMultiplier)
else (BUSTED):
  if replay.escaped: INVALID
  outcome = BUSTED
  mult = vaultReached >= 2 ? vaultMultipliers[vaultReached-2] : 1
  penalty = bustPenalty * (boosters includes "shield" ? 0.5 : 1)
  score = roundHalfUp(totalLoot * mult * (1 - penalty) * lootMultiplier)
```

`roundHalfUp(x) = floor(x + 0.5)` in both languages (positive values only).

The client sends `clientScore`; the server replays and rejects on mismatch. The server's number is the only one that ever reaches the leaderboard.

## 7. Plausibility bounds (server only)

- `durationMs ≥ totalMoves * 120` and `durationMs ≤ 6h`
- `totalMoves ≤ Σ (vault.moves + 3 + guardBonusCap)` where guardBonusCap = 20 per vault
- `len(replay.vaults) ≤ len(config.vaults)`
